\paragraph{A labour forecast at intake.}
\label{par:labour-reference}
The target at intake is the number of person-hours a new requirement will take through age $u=\tau+\Delta$. A simple benchmark uses earlier requirements in the same class. The class can depend on the request type or its initial size, both known when the request arrives. Before evaluation, choose the lookback period and minimum history size for each class. A broader class can serve as a fallback if its requirements are comparable.

For a task entering class $x$ at time $c$, let $D_c(x)$ comprise the eligible earlier tasks of that class whose labour windows had closed and whose hours the team knew by $c$. Tasks the team discontinued or had yet to finish when the labour window closed remain eligible. Each contributes its independently measured person-hours $h_j=H_j(u)$ under the same accounting rules. When the class meets the minimum history size, its forecast is
\[
 g_c(x)=\frac{1}{|D_c(x)|}\sum_{j\in D_c(x)}h_j .
\]
For example, three tasks with verified labour of $0$, $2$ and $4$ person-hours give a forecast of $2$. If some eligible tasks lack measurements, using the historical mean for all eligible work requires an assumption about those missing hours. The evaluation should identify those tasks and explain any adjustment or restriction to tasks with observed hours. When the original class has too few observations, the prespecified fallback must meet the same minimum. If both histories are too small, the team issues no forecast.

Historical hours predict future labour only to the extent that earlier tasks represent incoming work. A staffing or tooling change can alter how long a task takes. A change in how contributors report review time can alter the measured hours even if they spend exactly as long on the task. A prospective evaluation dates each forecast at intake and uses only the information available then. All versions of a requirement belong on the same side of the split between training and evaluation. The history size, contributing teams and calendar period identify the basis for each prediction. Signed errors before and after a change in staffing or tools can reveal systematic overprediction or underprediction. Score competing methods on the same tasks and report how often each method issued a forecast across all eligible intakes.

In a numerical check, five requirements supplied the initial history for eight later intakes at one synthetic team. Each forecast required two earlier measurements available at intake. The class mean gave seven forecasts, leaving the team's first migration without one. A mean pooled across task types covered all eight. On the seven common tasks the respective mean absolute errors were $1.19$ and $2.48$ person-hours against known labour. Within the bug-fix class, two later tasks each took six hours. The class mean predicted two hours for the first and $8/3$ for the next. Estimating these errors for real work requires independent measurements of labour on future intakes.

\paragraph{Sampling error in validation.}
Suppose the forecast and the true labour for a task both equal four hours. An estimate based on a sample of the team's time can still differ from four. That sampling variation affects the error we attribute to the forecast.

For a task with fixed labour $H$, let $f$ be its intake forecast and $\widehat H$ its labour estimated later, for example by \eqref{eq:difference-estimator}. Keeping $f$ fixed over the validation draws, suppose $\E_{\!s}[\widehat H]=H$ and the design variance is finite. Then
\begin{align*}
 \E_{\!s}[f-\widehat H]&=f-H,\\
 \E_{\!s}[(f-\widehat H)^2]&=(f-H)^2+\Var_{\!s}(\widehat H).
\end{align*}
Expanding the square gives a cross term proportional to $\E_{\!s}[\widehat H-H]$, which vanishes. Scoring against sampled hours therefore preserves signed error in expectation and increases expected squared error by the sampling variance.

Now compare $f$ with a second intake forecast $g$ for the same task, such as the historical class mean. If both forecasts are fixed across draws and scored against the same labour estimate, the variance term cancels in the expected difference,
\[
 \E_{\!s}[(f-\widehat H)^2-(g-\widehat H)^2]
 =(f-H)^2-(g-H)^2.
\]
For a single task the observed difference is $(f-g)(f+g-2\widehat H)$, with variance $4(f-g)^2\Var_s(\widehat H)$. Where several tasks share a sampled shift, uncertainty in the average difference must allow for covariance across those tasks. To estimate the squared error of one forecast against true labour, subtract an unbiased estimate $\widehat V$ of $\Var_s(\widehat H)$ from $(f-\widehat H)^2$. The corrected value can be negative on a particular draw and still average to $(f-H)^2$.

A systematic error in the reference hours can reverse a forecast ranking. With measurement bias $b=\E_s[\widehat H]-H$, the expected difference in squared errors shifts by $-2(f-g)b$. For a four-hour task, a reference that consistently misses an hour of review makes a three-hour forecast appear exact. The correct forecast then appears an hour too high. If an audit bounds $b$, the endpoints of that range show whether the ranking changes anywhere within the plausible range of bias.

Absolute errors and prediction intervals pose a different problem. Consider a task that fully occupies four of eight one-hour intervals, with allocations $(1,1,1,1,0,0,0,0)$. Its true labour is $H=4$ hours. Draw one interval uniformly, with inclusion probability $1/8$. The Horvitz--Thompson estimate is then $0$ or $8$ hours with equal probability. Scoring the exact forecast of $4$ hours against either sampled estimate gives an apparent absolute error of four hours. The interval $[3.5,4.5]$ contains true labour. Its coverage falls to zero when judged against the sampled estimates. These discrepancies arise solely from the choice of reference.

One way to evaluate these measures is to select validation tasks by probability sampling and check every contributor's eligible intervals against independent evidence. Any uncertainty about the reference hours leaves a corresponding range of possible forecast errors. A measurement model offers another approach if all measurement processes consistent with the observations give the same accuracy measure. Quantifying sampling uncertainty requires the relevant inclusion probabilities, including those for pairs where the design calls for them. Task-level errors show whether a forecast systematically misses high or low for a particular kind of work.

Scoring delivered work introduces another source of measurement error. Consider a requirement worth four reference units, one for each equally weighted criterion. It takes one person-hour. If three criteria still hold at follow-up, the rate is three units per person-hour, whether the implementation spans one pull request or three. If a reviewer marks all four criteria as satisfied, the reported rate rises to four units per person-hour even though one criterion failed.

Reviewers might themselves give a different score when a change spans several pull requests. Two reviewers could test this by scoring both versions, with one seeing the single pull request first and the other seeing the three pull requests first. Both versions must deliver identical behaviour on the same acceptance date. A second comparison can test how reviewers apply the counting rule when one component first passes acceptance after the cutoff. Report which criteria the reviewers scored differently and the proportion of tasks they assessed at follow-up. Repeating the comparison of working practices over plausible values for missing hours and disputed scores shows whether the preference depends on a specific unresolved observation.
